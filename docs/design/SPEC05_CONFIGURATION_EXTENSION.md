# Spec 05 native-only Training configuration extension

**Status:** additive native-app design requirements. **Not a change to the interactive HTML prototype.**

## Authority and scope

Read with [Spec 05](../specs/05-cnn-and-rf-training.md), [original screen parity](UX_PARITY_MATRIX.md), [alp-ui consumer contract](ALP_UI_CONSUMER_CONTRACT.md), [field catalog](../science/TRAINING_CONFIGURATION_CATALOG.md), [user-facing training Wiki](../wiki/TRAINING_CONFIGURATION.md) and [presets](../science/TRAINING_PRESETS.md). The original prototype is the baseline for navigation, layout and prominent action hierarchy. This document resolves what the **new scientific fields** should look and behave like *in the PySide6 app* because they are deliberately absent from the prototype. It does **not** authorize redesigning the app or adding prediction UI.

## Layout and progressive disclosure

1. Keep the current Train Model page breadcrumb and main title, the two-column composition, numbered **1 · Dataset** and **2 · Model configuration** hierarchy, and **Start Training** as a clearly identifiable primary action in the configuration panel. Preserve original dataset selector, CNN/RF family choice, essential defaults/controls, explanatory copy and status/error placements from the HTML. Compare the **collapsed default native state** against the unchanged `train` route and `rf-config-preview.png`.
2. **Primary controls are intentionally few:** only the following editable inputs appear directly in the always-visible Model configuration panel (besides Dataset and CNN/RF family selection): **Common:** optional Run name; **CNN:** sequence length, maximum epochs, batch size, learning rate, device; **RF:** number of trees, maximum tree depth, minimum samples per leaf. Do **not** add more exposed basic controls merely because the field catalog has many entries. Do not expose `rf_threshold` as a main training control: it is a future decision-policy setting, not an RF fit parameter. Preserve any corresponding prototype labels/placement where they exist; if the prototype shows another scientific basic control, keep its visual affordance but place it within More settings when the added field inventory would otherwise overcrowd the native panel, and log this additive design adaptation. Make the basics compact and understandable for first-time users. The exact primary keys are marked `ui_tier=primary` in the checked-in [machine-readable index](../science/TRAINING_CONFIGURATION_FIELDS.json); treat that roster as authoritative.
3. Put **Saved configurations** as a compact row directly below the CNN/RF family control, with an accessible selector (e.g. “Defaults”, saved preset names, “Unsaved changes”) and secondary **Save as… / Manage…** actions. This is **inside Model configuration**, not a new navigation destination. Management dialogs support rename, duplicate, overwrite and delete with confirmation. Never mutate a preset on changing a field. Do not put preset files inside the Collection.
4. Retain the prototype's Dataset/Model choice and prominent Start Training flow above the fold. The **single compact disclosure named “More settings”** (collapsed by default, showing a small modified-settings count/badge only when useful) reveals the **complete remaining configuration** organized by small, separately collapsible family-specific categories: CNN **Spectrogram**, **Normalization**, **Augmentation**, **Architecture**, **Optimization & validation**, **Execution**; RF **Forest**, **Acoustic features & preprocessing**, **Execution**. Put RF threshold in this detailed area and explain it is not used to fit the estimator. Use plain Qt scroll containers and public `alp-ui` controls where appropriate. **Neither open all subgroups automatically nor show all ~67 entries at once.** A single click on More settings should reveal short category headings and a compact summary, not an overwhelming wall of controls. Avoid a generic property grid, mandatory separate page, nested modal maze, or independent settings sidebar. Primary values always remain visible when this disclosure is closed. The detail groups are permitted to scroll vertically inside the existing page, but no horizontal scroll.
5. Default/derived fields can be read-only where the backend or Dataset determines them; **display the fixed `classifier.num_classes = 2` as derived, not editable. Never expose multi-label/multi-class switches, lists of simultaneous targets, or additional classification heads, regardless of toolbox support** ([binary classification scope](../science/BINARY_CLASSIFICATION_CONTRACT.md)). explain the reason. Hide irrelevant family sections, but **retain the unsaved draft** for both families during family toggling. Disable (don't imply support for) unavailable accelerators and other truly unsupported settings with specific contextual text. Avoid replacing the main CTA with preset actions. On narrow windows, stack the existing columns and make advanced content vertically scroll; avoid horizontal scrolling. Test keyboard traversal, screen-reader names and zoom/DPI.
6. **For every setting in More settings**, show its **current effective or editable value**, its **backend default**, and a **recommended starting value** with a clear origin/rationale and units (where applicable). The catalog’s `recommended_starting_value` initially equals the documented backend default; the agent must confirm it against the installed checkout before enabling the control for editable settings: label this “Suggested starting point (backend default)”, **not** an evidence-backed optimum. A derived/read-only field shows “Automatically determined” instead of a pretend recommendation. When default and suggestion match, a concise line like “Default / suggested starting value: 16” is fine; the two meanings must remain discoverable via tooltip/Wiki. Show source/version/context when a recommendation genuinely differs in future; don't invent universally optimal hyperparameters or silently substitute a suggested value during preset load. Make non-default overrides recognizable with a subtle indicator and offer **Reset field to default** and **Reset detailed settings to defaults** with appropriate confirmation for unsaved edits. Preset loading, switching families, collapsing/reopening and validation failures preserve edited values, not reset them. If a backend default is invalid for the selected Dataset/device, surface that incompatibility; do not falsely advertise the baseline as universally suitable.
7. Use stable labels, units and grouping from the [machine-readable field index](../science/TRAINING_CONFIGURATION_FIELDS.json) and [catalog](../science/TRAINING_CONFIGURATION_CATALOG.md). Every editable field has a focusable `alp-ui.HelpHint` adjacent to its label, with a concise **what/why/units** explanation plus a **specific Wiki anchor**. Read-only fields get accessible explanatory help. Link to the Wiki route/section, not a dead web address; focus return and context preservation are required. Error summaries should focus the first invalid control, retaining draft values; invalid form cannot launch a Worker. Avoid truncated HelpHint popovers in collapsed/scrolling panels.
8. Make **Start Training** resolve and validate a frozen full configuration snapshot. A prior preset is merely an optional origin label. Show a small summary of what will run (family, Dataset, device, main hyperparameters) without changing the prototype's primary CTA placement. No arbitrary directory selectors or reference-code command string builder.

## Test-first and evidence obligations

- **Red native tests before implementation:** assert a clean, collapsed first view has only the `ui_tier=primary` fields for the selected family; opening **More settings** reveals every `ui_tier=details` field under the appropriate family category. Test current/default/suggested values + recommendation basis text, derived-field behavior, reset actions, edited-value persistence across collapse/expand, family toggle and preset round-trip, keyboard disclosure, and complete config passed to Worker. A full always-open configuration panel is a failure.
- **Indexed red native tests:** `UT-TRAIN-007`/`008` (field coverage/validation), `UT-TRAIN-009`/`010` (preset rules), `IT-TRAIN-007`/`010`/`011`/`013`/`014` (real Qt form, validation, help/Wiki, storage, Worker snapshot). Assert every catalog field has an observable typed value and HelpHint/Wiki link; pick representative cross-field invalid combinations, true family draft isolation, genuine persistent restart. A screenshot by itself is not an assertion.
- **Native screenshot set:** `train-cnn.png` and `train-rf.png` for **prototype-equivalent collapsed baseline**; `train-cnn-advanced.png`, `train-rf-advanced.png`, `presets-list.png`, `presets-unsaved.png`, `presets-confirm-delete.png` for **new documented extension states**. Add a narrow/scroll focus case. Capture actual native Qt, compare baseline against prototype+Showcase and extension against this design brief+Showcase; update [evidence ledger](evidence/README.md). Never describe newly generated reference screenshots as coming from the HTML prototype.
- **Review gate:** verify collapsed screenshots prove a short, readable main form; expanded screenshots show compact category disclosures and at least one detailed field with its current/default/suggested values and matching HelpHint/Wiki route. Also inspect a non-default value and its reset control; no controls may silently vanish from the full frozen Run snapshot.
- **Owner review:** record which advanced sections are collapsed by default, which controls are read-only or unsupported and why, how action hierarchy remains intact, and feedback/focus behavior. Owner approval is required for any material deviation from the baseline; engineer may choose ordinary Qt layout specifics consistent with Showcase for the additive areas. Native `alp-ui` styling remains mandatory for controls; do not fork library internals.
- **No browser prototype changes:** Do not edit `docs/design/prototypes/training-first/{index.html,app.js,styles.css}` to satisfy these requirements. Changes to the baseline prototype are a separate owner-driven design decision; this spec requires **native implementation only**.
