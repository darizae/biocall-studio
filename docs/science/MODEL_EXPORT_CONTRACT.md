# Model export and structural reload contract — **Trainer-owned, no prediction**

**Owner:** Spec 05. Read with [Spec 05](../specs/05-cnn-and-rf-training.md), [source map](../agent/SOURCE_MAP.md) (scientific rows only), and the active `UT-TRAIN-*` / `IT-TRAIN-*` cases. This is the **training artifact boundary**, not an inference API. No scoring of new audio, segment detection, Prediction Run, CNN→RF cascade or Prediction UI is implemented or tested here. The future consumer and its **deferred** verification plan live in [PREDICTION](../PREDICTION.md).

## Saved configurations vs Model export

[Saved training presets](TRAINING_PRESETS.md) are mutable user-level templates. The Worker receives an **immutable, fully validated and resolved** CNN/RF Run configuration; Model export records every effective algorithm/transform setting from the [field catalog](TRAINING_CONFIGURATION_CATALOG.md), including nondefaults and applicable training-only settings as provenance. Neither a preset ID alone nor selected UI defaults alone is enough to reconstruct training settings. Structural reloading checks that the exported values match the actual execution record; **still no prediction or inference**.

## Publication schema (`model.json` + binary artifact)

All fields are owned by the immutable published Model, with portable relative paths inside the Collection and a versioned schema. Persist the **resolved** values used in the completed Run; do not rely on training defaults, a live Dataset directory for model internals, a developer `.venv`, the original pipeline checkout or environment variables to reconstruct the scientific configuration.

| Field group | Mandatory export information |
|---|---|
| Identity | `schema_version`, `model_id`, display label, `family` (`cnn`/`random_forest`), creation time, Run ID, Dataset ID and portable Dataset reference, artifact/export format versions |
| Input | explicit versioned `binary_single_label` task type; **exactly** `target` and `noise` with stable bijective two-index class→index mapping and positive-class identity; expected mono/channel policy, accepted sample-rate policy, window/segment duration and shape, precise preprocessing order and numeric parameters, time/rounding units; record which transforms are **training-only augmentation** vs **validation/production-compatible** |
| CNN | explicit two-class single-label output semantics and cardinality (`num_classes = 2`), no multi-label output; full encoder/classifier architecture configs; spectrogram parameters (FFT, hop, band limits, reference/minimum dB as applicable), normalization; checkpoint format/version and tensor state; optimizer/hyperparameters/seed as provenance (not required at future scoring runtime) |
| RF | exactly two estimator `classes_` aligned with persisted binary label mapping (never assume positive column index); exact mono/resample/short-segment padding policies, sample rate, filter bounds, MFCC/robust feature set identifier + extractor revision, **ordered exact feature names**, widths/dtypes and non-finite rules, estimator type/hyperparameters; `classes_` / probability class order and target class index, persisted threshold policy if selected (not assumed universal) |
| Results | measured train/validation split sample counts, metrics with explicit `null`+reason when undefined, selected validation/early-stop checkpoint and resolved hyperparameters; feature importances aligned with RF feature-name order |
| Integrity | relative artifact file paths, file sizes, cryptographic SHA-256s, source repo/commit + library/package versions and lock/wheel provenance sufficient to reproduce the training/export implementation, including the **actual separate `bioacoustics-dl-toolbox` upstream commit/version** when modified during this spec (not just the Trainer commit), and a verified bundled wheel for releases; record any intentional incompatibility/migration rules |

Use one canonical, versioned manifest schema with family-specific subdocuments. Units and names must be documented in [GLOSSARY](../GLOSSARY.md) and [ARCHITECTURE](../ARCHITECTURE.md); never write a field merely because a reference pipeline writes it. Do not copy **user source absolute paths** or private HPC machine identifiers into portable manifests.

## Spec 05 tests — **structural reload, not inference**

1. Train a genuine small **CNN** and **RF** using the *same published Dataset* with genuine source WAV-backed Snippets and actual validation. Preserve real measured metrics.
2. In a new process / after simulated application restart, read the published `model.json`, verify declared schema, contained paths, sizes/checksums and the actual binary. For trusted locally produced artifacts only, **deserialize** each family: CNN restore architecture/weight structure and declared class/config metadata; RF inspect restored estimator `classes_`, `n_features_in_`, optional `feature_names_in_` and exact ordered feature metadata. Check missing/wrong/corrupt models and manifests fail deterministically without publishing a completed Model.
3. Prove that **training-time and validation-time configuration values** (resampling/normalization/spectrogram and RF feature vectors) are represented in the saved manifest with exact order and units. Compare to actual training instrumentation, not made-up fixture dictionaries. RF validation may use `predict_proba` as part of the existing **training evaluation**, but do **not** build an independently callable segment scorer, run post-publication inference on arbitrary WAV, or perform predictions outside model training.
4. Assert artifact immutability, source audio non-mutation and reproducible publication/atomic failure handling. Include malformed-version, swapped-class-map, missing feature name, incorrect artifact hash and incompatible toolbox version tests.
5. **Required IDs:** `UT-TRAIN-001`…`UT-TRAIN-006` and `IT-TRAIN-001`…`IT-TRAIN-009` (the last two cover fresh-process artifact inspection and packaging independence). Case rows are defined in the [unit index](../UNIT_TESTING.md) and [integration index](../INTEGRATION_TEST_BEHAVIORS.md). See the [05c evidence ledger](../design/evidence/README.md#spec-05c--real-rf-training-and-phase-05-acceptance) for recorded cross-family execution; indexes and records do not replace executing tests in the actual checkout.

`torch.load`/`joblib.load`-style deserializers may execute code. Use only locally generated trusted artifacts and verify manifest/path/checksum before deserialization; no arbitrary imported binary Model feature is in the Trainer scope. Structural reload supports future compatibility **but does not scientifically prove inference parity**. The future Prediction app must establish that separately in [PREDICTION](../PREDICTION.md).
