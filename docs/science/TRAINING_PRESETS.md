# Saved training configurations — user presets (Spec 05)

**Owner:** Spec 05. **UI:** inside the existing Train Model / **2 · Model configuration** panel, immediately after family selector; do not introduce a top-level route or reorder Dataset → Model configuration → Start Training. Every setting has a `HelpHint` and [Wiki entry](../wiki/TRAINING_CONFIGURATION.md), as defined in the [configuration catalog](TRAINING_CONFIGURATION_CATALOG.md). **No inference or external file picker.**

## Product semantics

1. User can **Save as…**, **Load**, **Rename**, **Duplicate**, **Delete with confirmation** (and explicitly **Overwrite** an existing named preset) for CNN and RF configurations. Start from system defaults or last unsaved draft; a preset selector clearly distinguishes **Unsaved changes**. Native GUI must not imply that saving starts training.
2. **Reusable across Collections and Datasets:** store versioned, non-secret presets in the per-user OS application-data/config directory resolved by Qt (`QStandardPaths`), **not** under a specific Collection. The preset contains family + **all typed user-editable settings including detailed overrides whether More settings is open or closed**; `ui_tier` and recommendation metadata are presentation/catalog attributes, not per-preset overrides. The stored record contains all typed user-editable settings + schema version + label/identifier + create/update timestamps, source toolbox/pipeline schema revisions and optional non-sensitive notes. No Dataset/Collection/root/raw WAV path, Run ID, machine username, host or absolute directory. App-controlled storage is distinct from Collection-local immutable Run/Model artifacts.
3. **Binary scope:** presets must not contain a user-editable `classifier.num_classes`, multi-label task flags, target-class lists or per-class heads. Reject unsupported/legacy extra-class settings with an actionable compatibility error; do not silently coerce them to binary. The two-class `target`/`noise` mapping is derived from the validated Dataset ([scope](BINARY_CLASSIFICATION_CONTRACT.md)). Loading a preset updates only its own family-specific form draft; **never** changes the currently selected Dataset or launches a Worker. Keep draft edits separate from preset disk state until explicit save/overwrite. Switching family preserves its draft. If incompatibility/schema migration is required, show a comparison/warning and reject unsafe or unknown keys; do not silently delete values or invent defaults. At Run start, validate resolved current fields and snapshot them immutably into the Run spec. Every Model export records actual **resolved training settings**, not a mutable preset reference.
4. Persist with atomic replace + safe permissions; reject invalid field names/values, path traversal, duplicate normalized labels/IDs, corrupt JSON, unsupported schema/version and write failures without damaging existing presets. Preset names are display labels, not filesystem paths; derive safe opaque ID. Do not execute any serialized content or import arbitrary binary models.
5. A preset is an application-local convenience, **not a requirement for HPC or Git LFS**. Generated sample Collections/CI tests never rely on a developer’s actual preset directory. Use a redirected temporary QStandardPaths base or injected storage adapter during tests. Packaging must preserve/create writable app-local user-data storage after install.

## Native acceptance — red-first and prototype parity

- The **unchanged** interactive prototype contains no persisted preset UI. Add Save/Load/Delete/Rename/Duplicate only in the native app according to the [additive Spec 05 UX brief](../design/SPEC05_CONFIGURATION_EXTENSION.md), while preserving the existing prototype form hierarchy. The native app persists to OS user data. Use public `alp-ui` `SelectInput`, `TextInput` / modal confirmation, `Button`, `HelpHint`, form validation and alerts as available; inspect current exports. Do not add a bespoke visual system or modify unrelated prototype screens.
- `UT-TRAIN-009`: default + named presets; family isolation, roundtrip all typed keys, no filesystem/Dataset paths, change detection, overwrite/duplicate policy and immutable Run snapshot.
- `UT-TRAIN-010`: incompatibility, old schema, corrupt files, unsafe names, atomic interruption and migrated optional defaults produce explicit safe outcomes; no stale preset mutation.
- `IT-TRAIN-013`: actual Qt save/load/rename/duplicate/delete, restart persistence, keyboard/focus and HelpHint/Wiki deep links, current Dataset unchanged, real stored files, honest warning/error states.
- `IT-TRAIN-014`: starting a real Worker after loading a preset uses exact resolved values and preserves preset separately; editing/deleting a preset after completed Run leaves Model training record and checkpoint unchanged.
- `IT-MAC-004`/`IT-WIN-005`: installed apps can write/load presets and reopen Model, even when sibling checkouts are absent.
