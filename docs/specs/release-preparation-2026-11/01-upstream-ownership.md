# 01 — Adopt the released upstream spectrogram renderer and trim Studio

**Start gate:** toolbox [01 headless spectrogram](https://github.com/darizae/bioacoustics-dl-toolbox/blob/spec/2026-11-release-preparation/docs/specs/2026-11-release-preparation/01-headless-spectrogram.md) must have been implemented, reviewed, **released** per [toolbox 03](https://github.com/darizae/bioacoustics-dl-toolbox/blob/spec/2026-11-release-preparation/docs/specs/2026-11-release-preparation/03-release.md), and its wheel SHA-256 and tag commit recorded. Any new `alp-ui` code must similarly have passed [its release spec](https://github.com/darizae/alp-ui/blob/spec/2026-11-release-preparation/docs/project/specs/2026-11-release-preparation/03-release-candidate.md). Do not implement or merge library features within a BioCall Studio branch.

## Existing ownership (verified against original baseline)

`src/biocall_studio/review/workflows/spectrograms.py` holds NumPy-only STFT/channel-power/dB/palette/resampling plus Studio-specific rendering request and cache key. `review/domain/spectrograms.py` holds session-specific context, settings, frame/axis provenance and tiers; `review/application/generation.py`, `review/persistence/cache.py`, GUI and audio controller handle Qt workers, async loading, immutable result context and playback. The toolbox's existing `audio/transforms.py::Spectrogram` is a **different PyTorch model preprocessing** contract and is not a transparent replacement.

## Narrow downstream implementation

1. Fetch actual **published GitHub Release** wheel/sdist and immutable tag/commit for the latest approved toolbox version; verify hash and install in an isolated environment with the declared `[rf]` support, not an editable sibling checkout. Do the same for the released `alp-ui` version; ensure no old import shadows the wheel. Record package `__file__`, distribution version and exact upstream SHA.
2. Replace only duplicate numeric code in `review/workflows/spectrograms.py` with public toolbox NumPy calls. Keep `SpectrogramRenderRequest`, `SpectrogramMetadata`, `SpectrogramSettings`, `spectrogram_content_key`, cache versioning, sessions, validated WAV reads, queue/epoch logic, paints/overlays, `QMediaPlayer` and native user controls downstream.
3. Preserve exact mono/multichannel FFT/band mapping, peak-relative dB, palette, silence and frame-coordinate contracts. Use existing `tests/unit/test_review_spectrograms.py` and affected small integration cases for parity; make intentional non-parity explicit by incrementing algorithm/render/cache keys and ensuring cache invalidation, never silently reuse pixels.
4. Confirm ordinary public `alp-ui` widgets are sufficient. Only propose another **generic** upstream component in a new upstream version if evidence shows a second independent consumer; this is not a license to defer Studio on speculative UI abstraction.
5. Update `pyproject.toml` dependency constraints **and** `[tool.biocall-studio.science]` pinned upstream versions/commit SHAs together. Preserve re-installable release-wheel inputs and GPL/Qt licensing obligations.

**Checks here:** only focused deterministic renderer/unit/import/affected integration regressions, as suitable to a bounded VM. **Do not run Studio's complete suite in this spec.** It runs exactly once as the final downstream qualification, in [Studio 05](05-final-upstream-release-qualification.md), after both upstream releases, README trim and native installers.

**Acceptance:** less duplicated DSP, verified installed release origins, same scientific pixel/axis semantics or explicit migration, unchanged app state ownership and no unexpected new dependencies. If the toolbox deliberately did not ship a reusable API, stop and reconcile the release decision rather than import nonexistent code.
