# 04 — Hold BioCall Studio release/tag until macOS and Windows installers exist

This replaces the *unnecessary blanket* demand for new “genuine macOS Qt captures and audio playback” and “large real-data performance qualification”. Source-app **genuine Cocoa screenshots already exist** in `docs/design/evidence/release-real-data` and `docs/design/evidence/review-correction/native-rv10`; the baseline `QtMediaPlayback` and spectrogram behavior have existing tests. Do not add new screenshot, real-audio playback or long-duration/50k-performance projects as release gates.

**However, installers themselves have NOT been demonstrated by those screenshots.** The existing `docs/specs/06-macos-release-and-installer.md`, `07-windows-release-and-installer.md` and `docs/RELEASE_PROCESS.md` require an accuracy update: Review is implemented, not a placeholder; scope native installer verification to the smallest sufficient packaging/provenance checks, not repeated full Train→Detect→Review training journeys or a new scientific study.

## Final release sequence

1. After reviewed upstream releases, complete Studio source code/doc cleanup and run spec 03's base suites. Freeze exact versions/SHAs; prepare `v0.1.0a1` candidate notes, **uncreated tag** and artifact hash manifest.
2. **macOS native environment/runner, required:** build one installable BioCall Studio `.app` and distributable `.dmg` from pinned dependencies, with actual checked-in `assets/branding/icons/icon.icns`, Qt/torch/libs/fonts, Studio plus Train/Detect/Review and frozen `--worker` dispatch. Install/launch outside the checkout, verify app identity/icons, open each workspace, run minimal worker/load/export smoke with short fixture, restart and confirm no source tree/venv dependence. Verify signed/notarized/stapled Gatekeeper behavior **if this is advertised as public signed macOS distribution**. Record installer SHA and outcome; no fresh UX-capture suite.
3. **Windows native environment/runner, required:** build versioned x86-64 installer and app from the same reviewed source/dependency lock with `assets/branding/icons/icon.ico`; fresh install, launch workspaces, execute minimal bundled worker/load/export smoke, basic file/per-user path and uninstall preservation checks, and verify signatures **if required by public distribution policy**. Record binary/installer SHA. VM/CI on a real Windows runner counts; a Linux-generated binary or macOS source capture does not.
4. **License/security decision before distribution:** BioCall Studio's own license, GPL-3.0-only toolbox compatibility, PySide6/Qt LGPL/commercial obligations, embedded third-party notices, redistributability, and source-offer/installer compliance must be documented. A badge cannot supply missing legal rights. Failure blocks public installers.
5. **Only when BOTH installer gates pass** and owner approves: create immutable annotated `v0.1.0a1` at verified merged `main` SHA, publish GitHub release with the **tested** macOS and Windows installer binaries, actual SHA-256 digests and concise human notes. Never auto-promote, invent tag creation, or overwrite a published tag. If macOS and Windows differ in readiness, keep the release candidate/tag unpromoted rather than claiming both.

## Tool boundary

**GitHub API:** source PRs, notes, CI status, commit/tag verification (actual annotated-tag creation and asset upload may require a Git-capable VM/CI or another permitted GitHub endpoint, not merely the current connector). **ChatGPT VM:** static packaging setup, base tests, manifest/hash calculations and wheel building. **Native macOS/Windows:** actual freeze/sign/notarize/install/launch/uninstall. These are the only required local/native release tasks; not generic recapture, manual playback devices, endurance or large-data benchmarks.

**Acceptance:** installers are real, cross-platform, appropriately licensed, smoke-tested and checksummed; exact source/dependency/tag identity reproducible; both artifacts attached before calling the release complete. Pending native work is explicitly **blocked**, not “complete”.
