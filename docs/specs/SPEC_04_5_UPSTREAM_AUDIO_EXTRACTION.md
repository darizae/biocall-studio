# 04.5 — Move reusable audio extraction to `bioacoustics-dl-toolbox`

**Scoped references:** [toolbox upstream change procedure](../agent/UPSTREAM_TOOLBOX_WORKFLOW.md); [source map](../agent/SOURCE_MAP.md) (toolbox only); [Dataset extraction policy](../models/WORKFLOW_RULES.md) §2; exact `UT-AUDIO-*` / `IT-AUDIO-*` definitions below; [fixture classes](../INTEGRATION_TEST_DATA.md) as needed.

**Order:** implement after [04 — Worker & Runs](04-runs-and-worker.md) is accepted, **before** [05 — CNN and RF Training](05-cnn-and-rf-training.md). This is a **mandatory architectural extraction with behavioral equivalence**, not a new UX feature. Work in **two sibling Git repositories**, each with its own branch, tests, and commit. Do not rewrite accepted Specs 01–04, change the interactive prototype, start inference, or start Spec 05 in the same task.

## Why and the exact starting seam

The inspected Trainer snapshot contains `src/alpaca_desktop/computation/audio.py`. Its `extract_pcm_segment()` seeks and copies uncompressed PCM WAV frames into a new Snippet WAV using bounded chunks; `_millisecond_frame()` maps integer source-time milliseconds to frames; `ExtractedAudio` describes its result. `workflows/dataset_build.py` calls extraction for **both** `target` and `noise` Snippets; `persistence/datasets.py` also imports `sha256_file()` from this module.

Ownership after this spec:

| Existing responsibility | Target owner | Non-negotiable boundary |
|---|---|---|
| Actual frame arithmetic, seek/read, bounded PCM slicing, PCM output, audio sample/channel/frame facts | **`../bioacoustics-dl-toolbox`**, under a verified public `bioacoustics_dl_toolbox` API | Reusable and Qt-free; no Collection/Run/Dataset concepts; no imports from `alpaca_desktop` |
| Cancellation *signal*, path containment, symlink/collision policy, target/noise selection, Run/Worker progress, staging and final publication | **Trainer application/workflows/domain/persistence** | Use a thin callback/adaptor only if needed; the toolbox can accept a generic optional cancellation predicate or cancellation exception, without knowing the GUI or Run state |
| Snippet transform metadata serialization and versioned policy `pcm-preserve-nearest-frame-v1` | **Trainer adapter/manifest contract**, based on typed toolbox extraction facts | Keep manifest field names, values and serialization stable for Datasets already published by Spec 03 |
| General-purpose chunked `sha256_file` used to verify immutable artifacts | **Trainer persistence/integrity** (or an existing suitable Trainer infrastructure module) | Hashing is not a bioacoustics scientific algorithm; keep streaming/cancellation characteristics and move both import sites |

The *entire current `alpaca_desktop/computation` package must have no remaining scientific implementation or callers* after migration. Remove the now-empty package; do **not** retain a shadow implementation or compatibility copy in Trainer. If other computation files have appeared in the **live** checkout, inventory them first and migrate **only** scientifically reusable code with verified tests; document any app-specific code that must be relocated within Trainer. Do not mechanically move `workflows/`, `domain/`, or `persistence/` upstream.

## Before coding — evidence and API design

1. Check `git status --short --branch`, current commits and Python environments in **both** repos. Work from the current live checkout; never overwrite agent work. Inspect current `src/alpaca_desktop/computation/` **and all its callers**, plus `../bioacoustics-dl-toolbox` source/test/package layout. The local toolbox was **not included in the handoff**: no upstream symbol/path is assumed to exist just because the `alpaca-pipelines` repository contains a similarly named package. If the toolbox is missing or dirty in conflicting ways, report a blocker rather than copying code into Trainer.
2. Determine whether toolbox already provides an equivalent bounded, raw-PCM-preserving segment extraction API. If yes, test it against this spec before use; if not, add the smallest **public**, typed, documented upstream function in its existing audio I/O module (or a justified small module). Do not build a parallel audio framework. Keep the tested public API independent of PySide6, `alpaca_desktop`, Collection-relative paths and process managers. Preserve Windows/macOS portability.
3. Establish a **golden behavior baseline** from the current Trainer: source and output WAV bytes, exact source-time-to-frame endpoints, transform metadata, and failure/cancel effects. Cover common sample rates including **44,100 and 48,000 Hz**, mono and stereo, multiple supported uncompressed PCM sample widths, fractional-frame boundaries and file-end intervals. Use generated deterministic WAVs; no HPC or bundled `tests/data` is required.
4. Confirm the existing rounding policy (nearest source frame, half-open `[start_ms, end_ms)`) and exact `AUDIO_TRANSFORM_POLICY` value. Do **not** introduce resampling, mixing to mono, normalization, lossy conversion, changed headers or source mutation. Any behavior/format change is **out of scope** until separately approved and versioned; fail closed if fidelity cannot be preserved.

## Implementation — tests first, upstream first

1. **Red upstream:** write real WAV-based failing toolbox tests for its public extraction seam. Assert frame-accurate identity of raw PCM payload and metadata; reject invalid bounds, truncated/corrupt/non-PCM input and existing destination; verify cancellation and injected I/O failure never leave a seemingly valid output. Do not merely assert that a mocked reader was called. Keep bounded reads/writes and no-clobber behavior. Verify scope and semantics of generic cancellation; Trainer-specific errors are translated in the adapter.
2. **Green upstream:** implement or adapt the toolbox API with only the functionality needed. Run its targeted tests and appropriate existing suite/lint; write documentation and a minimal versioned/compatible API change. Run `git diff --check`; commit **in `../bioacoustics-dl-toolbox`** on `feat/pcm-segment-extraction` (or justified branch), record real full SHA, status and test results. Do not publish, merge or push unless separately requested.
3. **Reinstall and prove import source:** in the Trainer `.venv`, reinstall from `../bioacoustics-dl-toolbox` using its verified package metadata (e.g. `.venv/bin/python -m pip install -e ../bioacoustics-dl-toolbox`). Check `bioacoustics_dl_toolbox.__file__`, import the **new public symbol**, and verify the import does not resolve to the embedded copy under `../alpaca-pipelines`. Do not use global `pip`, a copy of toolbox source in Trainer, or `sys.path` shims.
4. **Red/green downstream:** replace extraction calls in `workflows/dataset_build.py` with the upstream API through the smallest app-owned adapter needed to preserve `ExtractedAudio.to_dict()`-equivalent metadata and the `pcm-preserve-nearest-frame-v1` policy. Move generic file hashing to Trainer-owned integrity/persistence code; update both `workflows/dataset_build.py` and `persistence/datasets.py` imports. Preserve cancellation exception translation, path containment, all staging cleanup and immutable manifest publication. Remove `src/alpaca_desktop/computation/` when no caller remains. **No synthetic no-op facade** wrapping the prior algorithm.
5. Execute previously passing `UT-DB-*`, `IT-DB-*`, `IT-RUN-*` where applicable, plus the new `UT-AUDIO-*`/`IT-AUDIO-*` cases from the test indexes. Check **newly built and already published** Dataset reopen, complete file/manifest checksums, no source WAV mutations and correct underfill/cancel/failure behavior. Test the actual `.venv`/Worker import in a **fresh subprocess**, not only an in-process import. Inspect/repair any newly surfaced desktop paths in the live checkout.
6. Commit the Trainer integration separately on `spec/04.5-upstream-audio-extraction` (branch naming may follow actual repo policy). Report both SHAs, dependency metadata, reinstall and import path, exact test commands/results, and clean trees; update reproducible dev dependency constraint and release wheel provenance. If the migration is blocked or any compatibility/acceptance gate fails, **do not proceed to Spec 05**.

## Exact acceptance cases — not covered until implemented and run

- **`UT-AUDIO-001`** (Trainer, Qt-free): millisecond/frame interval and adapter policy/metadata mapping retain current `pcm-preserve-nearest-frame-v1` semantics; reject invalid timing and mismatched frame facts; no training-time resampling assumptions.
- **`UT-AUDIO-002`** (Trainer, Qt-free): portable manifest representation and streamed artifact checksum remain stable; cancellation/error classes are translated without leaking library-specific UI/Run concepts.
- **`IT-AUDIO-001`** (real WAV + toolbox): raw PCM payload and WAV frame/header facts match the approved pre-migration baseline for target and noise slices across stated audio formats and boundary cases; input bytes untouched.
- **`IT-AUDIO-002`** (real files + toolbox): existing target, invalid boundaries/codec/truncated source, cancellation during chunk copy and write errors do not overwrite or leave staged/published partial Snippets.
- **`IT-AUDIO-003`** (Trainer workflow/publication): real post-migration Dataset Build produces the same transform policy/interval/provenance/target-noise labels, valid hashes/partitions/splits and safe cancellation/underfill behavior as Spec 03. Reopen previously published Dataset artifacts unchanged.
- **`IT-AUDIO-004`** (installed `.venv` + subprocess/Worker): actual build path imports the newly committed **separate toolbox**, never the pipeline's embedded copy or the removed `alpaca_desktop.computation`; dependency version/SHA resolved and reported; no checkout-specific path is persisted to Dataset manifests.

Upstream tests belong inside the toolbox checkout under its own conventions; the indexed `IT-AUDIO-*` tests belong in Trainer and must assert a **real cross-repository boundary**. Associate them with existing [`TD-WAV`, `TD-SPLIT`, `TD-FAIL` and `TD-PATH`](../INTEGRATION_TEST_DATA.md) classes. Use [unit index](../UNIT_TESTING.md), [integration index](../INTEGRATION_TEST_BEHAVIORS.md) and the [upstream-first delivery workflow](../agent/UPSTREAM_TOOLBOX_WORKFLOW.md). No new UX, native screenshot, inference, multi-label or HPC fixture task is created by this backend-only spec.

## Blocking definition of done

- Public toolbox API works on reproducible real WAVs, with committed upstream source/tests; desktop imports and uses it in an actual Dataset Build. No scientific algorithm remains under `alpaca_desktop/computation/` and generic hashing is correctly owned by Trainer.
- Bytewise extraction and **already published Dataset compatibility** are demonstrated, including stable policy metadata and cancellation/failure effects. Existing dataset/worker integration tests remain green, or a concrete blocker is reported.
- Both repos have separate tested commits and clean worktrees; the Trainer `.venv` resolves to the intended library revision. The dependency is reproducible for eventual `.app`/`.exe` wheels, not dependent on the developer sibling directory after packaging. No automatic upstream publication.
- No HTML prototype/UI changes, no inference, no new taxonomy/classes. **Spec 05 starts only after Spec 04.5 is accepted.**
