## Audio, spectrogram and interaction contract

**Input:** each *eligible* candidate's original WAV window around its original frame interval. Default initial context approximately 2 seconds before/after, clamped to `[0, recording.frame_count]`. Keep original `start_frame/end_frame`, rate and exact displayed time anchors; mark the detected interval on the spectrogram. Adjacent/overlapping candidates may share intermediate source reads/transforms if it improves measured performance, but each remains a distinct label and UI item. Do not accidentally export the *context* audio instead of the detected interval.

**Render:** use reproducible, explicit spectral settings (sample rate/channel handling, window, FFT, hop, frequency range, amplitude scaling, image dimensions, color scale, renderer version). Establish readable defaults with representative normal audible-call WAVs in RV-03; never silently borrow inference-time mel feature preprocessing if it is unsuitable for human inspection. If audio is multichannel, decide/test a display/playback channel policy without modifying stored source. Prefer CPU bounded decoding and small memory windows, not a GPU dependency. A lightweight thumbnail for Gallery and a high-detail view for One by one should share computation where justified and not require 50,000 full-resolution images. Native Qt UI should scale/zoom images legibly without a full recording timeline.

**Audio:** Play/Pause, basic seeking within the displayed candidate-context clip, explicit Previous/Next, stop/transition on navigation, single active playback and no overlap between rapidly switched items. Play the context clip at natural speed, highlight the detected interval; let users hear the full surrounding signal. Relinking/stale source and unsupported PCM/decoder errors must be visible and actionable; a missing source never implies silence. Audio playback and annotation remain responsive during background generation, eviction or export. Handle device unavailable, stream failure, cancellation, selection change and window closure with real Qt multimedia tests. Native media failures must not mutate labels.

**Navigation:** Gallery = lazy image grid plus visible status and human-readable recording/time; List = `alp-ui` DataTable/model-view/proxy with sorted searchable/filterable rows and bulk selection; One by one = largest spectrogram, audio controls, statuses and Previous/Next. Labeling Call/Not a call saves and auto-advances to the **next Unreviewed eligible candidate**; if none remain, keep user in a valid stable state rather than wrapping unexpectedly. Explicit Previous/Next traverse the current sequence and allow revisiting already reviewed candidates; **fixed** keyboard shortcuts mirror buttons and follow the exact home-row mapping, focus exclusions and pointer/focus tooltip wording in [RV-05](RV-05-native-review-ui.md#fixed-review-keyboard-shortcuts-and-tooltip-contract--owner-requested-design-clarification-pending-prototype-sign-off). Switching views preserves filters/current item/selection; selection labels operate on persistent candidate identities, not visual indices. In list/gallery, selection and bulk cache flush need safe multi-select, with no per-row Qt widgets. Plain status icons must be distinguished by shape and text as well as color.

**Scale:** >=50,000 candidates must use incremental indexed paging, bounded QAbstractItemModel/proxy updates, viewport-based thumbnail requests and bounded state. Never construct tens of thousands of heavyweight widgets/images on initial load. Filters/sort/search should rely on database/index or bounded model ranges, not decoding images. Scrolling, label updates, keyboard actions and audio controls must keep the real Qt event loop responsive under load. Establish measured latency/memory budgets on actual available hardware, reporting distribution, cold vs warm cache and model/recording scale.

## Owner-approved spectrogram scientific scope and axis contract (2026-11-03)

**Pre-implementation gate:** execute/review [spectrogram pre-spec investigation](SPECTROGRAM_GENERATION_INVESTIGATION.md) first; [owner decision log](SPECTROGRAM_DECISIONS.md) approves the control *scope* and channel/normalization policy, **not** unmeasured native speed, exact numeric rounding, image tiers or cross-language parity. Source clips are original candidate interval with selected 1/2/3 s context on *each side*, clamped to verified source `[0, frame_count)` with **no fabricated 0.12 s silence**. Preserve exact original candidate boundaries for export. Relative intensity is computed in dB against the **peak within the displayed image band**, not a fixed between-recording SPL/volume scale. **Contrast** adjusts visible relative dB floor (proposed 40/50/65). For stereo and supported multichannel inputs, compute independent channel FFT **power** then average the powers; do **not** average waveforms and cancel opposite-phase signals. Original multichannel playback and WAV export remain unchanged.

Default visible ceiling **4.2 kHz**, researcher switch to 3 or 8 kHz subject to Nyquist; linear frequency, Magma default, Viridis optional. Simple **Sound detail** chooses named short/balanced/long symmetric-Hann STFT windows; Balanced preserves historical 2,000 samples, 2,048 FFT, hop 1,000 at 48 kHz. Minimal Advanced may override the precise sound window, overlap (50/75%) and low-frequency floor. FFT zero-padding, one-sided power conventions, frame-center policy, sample-rate adaptation, peak/zero handling, interpolation and decibel conversion must be proven with real numeric fixtures before the final native settings schema is locked. Do not silently use mel/PSD from Detect or default centered/padded SciPy STFT. Palette and contrast are display choices; context/window/stereo/band alter represented samples/spectrum. User tooltips must convey the time-frequency trade-off without DSP jargon in main UI.

**Image/axis separation:** encode **only** spectrogram data in cached raster; no axis, times, labels, detection marking, colour legend or manuscript text. A versioned metadata record includes verified recording identity/rate/channels, exact source and clipped context start/end **integer frames**, actual STFT frame centers and frequency-bin centers/edges, interpolation/pixel extent transform, `f_min`, actual Nyquist-bounded `f_max`, image dimensions/tier, orientation, linear scaling, current settings+renderer versions. Native `QPainter` draws axes and detected span from this *same transform* within one DPR-aware `QRectF`; Gallery compact highlight and One by one ticks must not derive from hardcoded six seconds or 8 kHz. List remains dense without unnecessary tiny axes. Test source-end truncation, high-DPI resize, zero/short clips and offset matching to exact original frames.

**Qualification extension:** `UT-REVW-005/006` and `IT-REVW-004/005` add numeric R-reference tolerances, phase-opposed stereo, sample-rate/FFT+decibel choices, no fabricated context, axis/pixel/detection edge alignment and real native Qt rendering. Thumbnail vs detail must share consistent coordinates but need not cache every detail.
