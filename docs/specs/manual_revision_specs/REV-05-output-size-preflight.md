# REV-05 — Shared output-size and free-space preflight

**Status:** proposed; specification only. **Base:** reviewed current `main` after REV-04/ST-11 source qualification. **Branch when authorized:** `studio-rev05-storage-preflight`. Train and Detect are in scope; Review is a future consumer, not a new workflow in this revision. Installer/release qualification is out of scope.

## Outcome and ownership

Before starting a disk-writing operation, show researchers an intelligible estimate of **output size**, the **space required while it runs**, and **free space at the destination**, followed by an informed Start/Export decision. Do not claim that processing time or output size is known exactly when it depends on CNN detections, Model weights, settings or disk behavior. Do not turn the preflight into a dashboard, persistent wizard or a separate Run.

- `shared/` owns only a **Qt-free**, versioned, bounded `StorageEstimate` decision/formatting service (sizing arithmetic, confidence, validation and capacity comparison). A narrow platform adapter queries local filesystem capacity; no Run, Collection, UI or scientific algorithm moves into shared.
- **Train** owns its Dataset Build and CNN/RF Training estimate inputs, destinations and confirmation in the existing start action. **Detect** owns its CNN/RF metadata-Result and corpus-export estimates/confirmation. Each workflow supplies its own artifact planner and retains its own Worker, Run, logging, source-freshness and publication rules.
- **Review** may implement a separate adapter later, consuming this contract only when Review actually has an output-producing operation. No Review UI, fake output or cross-workflow run is added now.
- Follow [`AGENTS.md`](../../../AGENTS.md), [agent routing](../../agent/ROUTING.md), [UX principles](../../design/UX_PARITY_MATRIX.md), [current researcher-facing UI](../../design/UX_PARITY_MATRIX.md) and the owner feedback in [`detect-revision-notes.txt`](detect-revision-notes.txt) / [`UI-pass-revision-spec.md`](UI-pass-revision-spec.md). This document specifies only new behavior and copy, not a second UI style guide.

## Evidence and calculations — verify before implementing

1. Inspect **actual** Train Dataset materialization, CNN/RF checkpoint/log staging, Detect inventory/CNN/RF Result serialization, and WAV/Raven export code and receipts; identify exact output roots and staging locations. Read existing histories **locally** first (completed Run/Artifact/Export receipts). Examine permitted historical HPC data **only after separate source authorization** and through the scoped read-only HPC route in `docs/priv/hpc-source-access/SKILL.md`. Collect only aggregate counts, source durations, audio format, resolved settings, output byte sizes and processing categories needed for calibration; do not pull whole WAVs, scan unrelated directories, issue remote jobs, expose usernames/host paths or make HPC a runtime dependency. Record provenance, cohort size, representativeness and limitations; if inaccessible, mark calibration unavailable and use defensible analytical bounds. Historical data are empirical calibration, not universal truth.
2. Frozen inputs include operation kind, eligible **file count**, validated source **frame counts and sample rates** (duration = frames/rate), format facts, selected intervals, relevant Model architecture/configuration and output path(s). Reject stale/invalid/unreadable inventory or unsafe destination; never silently treat missing files as zero bytes. Recompute when selection, configuration, destination or relevant capacity facts change, and recheck immediately before Worker admission.
3. Use **binary units**, consistently: `1 KiB = 1024 B`, `1 MiB = 1024 KiB`, `1 GiB = 1024 MiB`. Display whole bytes only where appropriate; round estimated quantities **up** to a readable precision, never round a positive estimate to `0 KB`. For user-facing copy prefer `KB`, `MB`, `GB` (or `TB`) consistently, without scientific notation or developer/internal IDs; state the 1024 basis once in the user guide, not in repeated captions. Guard integer overflow/NaN, zero-duration, enormous selection and mixed formats.
4. **Deterministic sizing where possible:** Train Dataset Snippets use planned frame/sample-width/channel counts plus WAV headers, split/manifests and bounded staging; Detect corpus snippets/concat use the already frozen interval frame counts, actual PCM encoding, per-file headers, TSV/provenance overhead and export mode (`snippets` / `concat` / `both`), without counting the same file twice. Respect existing unsupported mixed-format and collision policies. If an operation writes to different filesystems, check them separately; never add free space across volumes.
5. **Uncertain sizing:** CNN/RF Model artifacts depend on actual architecture/forest structure, checkpoints, epochs, logs and retained intermediates; CNN Results depend on window/hop count and how many candidates survive threshold/merge; RF derived Results depend on actual candidate count. Use verified upper bounds where available, or a plainly labeled **range** backed by the appropriate measured cohorts and conservative padding. Worst-case window count and JSON/row ceilings must honor current schema limits. Do not invent precise predictions, confuse input audio bytes with model/output bytes, or promise a maximum without proving it.
6. `StorageEstimate` records: version, operation, frozen input/config digest, target volume(s), expected final bytes (`exact | range | unavailable`), peak additional bytes (includes **staging, retries/temporary copies, retained checkpoints** as applicable), confidence/basis (`arithmetic | measured | insufficient evidence`), observed free bytes/time, reserved headroom policy, and `ready | tight | insufficient | unknown | stale` decision with reason. Do not store source absolute paths or HPC-derived identities in portable artifacts or diagnostic logs. No persisted disk reservation is implied; other programs can consume space.
7. Capacity rule: compare **peak additional bytes + conservative reserve** against free bytes on **each** destination volume, using documented reserve policy (initial floor `max(512 MiB, 10% of estimated peak)`; revise against evidence and small-volume usability). A missing/denied capacity query is **unknown**, never “enough”. If peak cannot be bounded, show the uncertainty and require explicit confirmation; if known space is insufficient, disable Start/Export and offer **Change destination** when supported. If tight, require explicit confirmation; if ready, the existing Start/Export button is sufficient. Recheck once at start, and enforce normal Worker disk-full, cancel and atomic cleanup behavior independently of this estimate. Preflight is **not** a guarantee or a substitute for staging/publishing safely.

## Native UI and proposed copy (approval required)

Integrate one compact **Storage** section into the existing Train Build/Start Training and Detect Run/Export preparation screen only when there is a proposed output. Put information beside the actual primary action, not in a new route, floating caption, decorative alert or repeated explanatory card. Keep the active destination discoverable; show its drive/folder label only when useful. Do not display technical digest, filesystem identifier, algorithm/model-internal size multipliers, “immutable”, “source-time”, “backend”, or separate storage status badges. Use normal text size, accessible contrast, keyboard focus and actual Qt confirmation.

| Condition/control | Visible text | Contextual HelpHint (only if user needs it) |
|---|---|---|
| Selected inputs (only if not already visible) | **{count} files · {duration} of audio** | Omit; the values explain what is being estimated. |
| Section and value | **Storage** · **Estimated output: about {size}** (or **{low}–{high}**) | **Estimated output:** “Approximate space the finished files will use.” |
| Peak intermediate usage | **Space needed while running: about {size}** | **Space while running:** “Includes temporary files. Some are removed when the task finishes.” |
| Capacity | **Free on {destination}: {size}** | Omit; self-explanatory. |
| Uncertain output | **Output size varies with the recording and settings.** | Omit; avoid pseudo-precision. |
| Unknown output size | **Can't estimate the output size yet. Check the selected files and settings.** | Omit; actionable state belongs inline. |
| Unknown free space | **Can't check free space on this destination.** | Omit; explicit confirmation required. |
| Tight space | **Storage may run low while this runs. Continue?** | Omit; one confirmation with **Cancel** / **Continue**. |
| Insufficient space | **Not enough free space for this operation. Choose another destination or free up space.** | Omit; Start/Export disabled. |
| Normal action | Keep current **Build Dataset**, **Start Training**, **Start detection** or **Export** label | Omit; do not introduce a redundant “Proceed?” dialog when clearly safe. |

All sample wording above is *proposed*, not silently approved product copy. Inspect the current nine Detect HelpHints and Train field hints, retain their plain-language conventions and submit only new/changed strings for owner approval **before** implementation. Use consistent locale-aware numeric formatting and accessible non-color-only status. No unsolicited tooltips on every value, extraneous subtitles, overlines, repeated status alerts or tiny captions. Avoid saying “we”; tests must assert the exact approved strings and keyboard accessibility.
