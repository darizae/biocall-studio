## Deliverable and boundaries

1. Inspect the actual local `../alpaca-pipelines` RF training, `rf/audio_features/` and `rf/audio_preprocess.py` functions/tests and SHAs. Establish the *exact ordered* robust+MFCC acoustic feature names/schema and mono, resampling, window/padding, band, dtype and non-finite policies; verify any equivalent toolbox helper before reusing it. Avoid importing pipeline application schemas or silently changing feature defaults. Keep scientific algorithms at their justified upstream owner, Trainer-specific adaptation at the Worker boundary.
2. Use 05a's fully validated typed RF config to fit a real deterministic, binary **single-output** scikit-learn `RandomForestClassifier` on actual Dataset `train` Snippets; evaluate on `val` only. Check estimator `classes_` and target probability-column mapping explicitly; reject missing or extra classes, multi-output fitting and mismatched ordered feature matrices. `rf_threshold` is saved decision-policy metadata, **not** a fitting control; do not implement inference/scoring on arbitrary audio.
3. Extend 05b's **one canonical** Model format with RF estimator bytes, exact feature extractor revision/names/order and preprocessing, mapped `classes_`, resolved settings, measured metrics and ordered feature importances. Fresh-process trusted reload validates schema, portable paths, SHA-256, estimator `n_features_in_`/`classes_`, feature compatibility and class order before treating any Model as usable. Preserve atomic no-clobber publication and cancellation cleanup; never modify Dataset/WAVs or previously published CNN Models.
4. Show genuine RF **extract → fit → validate** stage progress and ordered bar `alp-ui.Plot` feature importances with numeric alternatives, not fabricated RF epoch loss. Keep CNN line plots and both Model detail views truthful when metrics are undefined. Verify native collapsed/advanced settings, preset actions, Model/Run views and prototype/Showcase parity without modifying the HTML prototype.
