## Deliverable and boundaries

1. **Verify scientific ownership first.** Inspect local SHAs, tested public architecture/trainer/checkpoint/preprocessing interfaces and editable installation of **separate** `../bioacoustics-dl-toolbox`; prove its actual imported module wins over the package copy in `../alpaca-pipelines`. Use that toolbox for CNN algorithms; the pipeline is a targeted behavior reference, not a runtime Run manager. Fix genuine reusable defects upstream and report separate tested commits/reinstallation, never silently vendor or patch around them.
2. Consume real immutable, integrity-checked Dataset Snippets using the existing Worker lifecycle. Validate safe paths, provenance, `train`/`val` source grouping, coverage of exactly two mutually exclusive labels and stable class→index meaning. Reject missing/unsafe/malformed/multi-label input before publish; train only on `train`, evaluate on `val`.
3. Implement a **genuine bounded CPU** categorical two-output CNN training run (GPU only if verified). Resolve every applicable 05a field against *actual* library behavior; use correct transforms, spectrogram/normalization, train-only augmentation, architecture, optimizer, seed, epochs and early stop. Measure real epoch train/validation loss and metrics, preserving undefined values with reasons. Emit supervised progress/cancel/failure through the existing Run boundary; no invented success or plots.
4. Build the **single versioned Model publication/reopen foundation** in Trainer persistence: family-tagged `model.json`, immutable Dataset/Run links, complete resolved scientific settings, class map, portable relative binary paths, checksum/size, metric/undefined reasons, versions and actual source/library provenance. Stage and verify before exclusive no-clobber publication; errors/cancel/corruption leave no completed Model and do not change inputs. Implement the CNN-specific checkpoint schema and a fresh-process **trusted structural** reload checking config, tensor/state and declared two-class head. Validate manifest/path/hash *before* deserializing trusted local bytes; do **not** score new WAVs. Leave RF-specific serialization/validation to 05c, not a fake RF artifact.
5. Populate the native CNN Run/Model experience using measured epoch line series via public `alp-ui.Plot` and accessible numeric data; ensure prototype/Showcase parity. The later RF family must share Model identity, immutable publication, metrics and UI conventions without duplicate infrastructures.

## Tests and exit

Write failing tests first; **`UT-TRAIN-001`/`004`/`005`** and **`IT-TRAIN-001`** are the primary fully owned IDs. Use a genuine small two-class source-WAV-backed published Dataset for CPU training, inspect the frozen Worker spec vs effective library settings, validate real persisted loss/metrics, verify destructive-path failures and structurally reopen the exact locally generated checkpoint in a fresh subprocess. Capture real CNN Train/Run/Model screenshots and update the [native evidence ledger](../design/evidence/README.md).

CNN assertions for the **shared** IDs (`UT-TRAIN-003`, `IT-TRAIN-004`–`009`, `012`, `014`) are useful incremental tests but **do not close those IDs**: the indexed behaviors require both families and/or real preset-to-Model checks. No RF result, full Spec 05 acceptance, packaging independence or Prediction claim belongs to 05b. Finish with verified tests/evidence and a scoped [Git handoff](../agent/GIT_DELIVERY.md); report separate upstream SHA if applicable.
